# App Store Review Analysis API

A service that collects Apple App Store reviews, processes them, and runs a multi-method NLP/LLM analysis pipeline: rating metrics, sentiment analysis (VADER, Transformer, LLM), negative keyword/phrase extraction (TF-IDF, spaCy, KeyBERT), and LLM-generated product insights. Results are served through a FastAPI REST API.

---

## 1. Running the API Locally

### Install dependencies

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate

pip install -r requirements.txt
python -m spacy download en_core_web_sm
```

### Configure environment variables

Copy `.env.example` to `.env` and fill in the required values:

```env
FETCHLAYER_API_KEY=
GROQ_API_KEY=
HF_TOKEN=

LLM_PROVIDER=ollama
OLLAMA_HOST=http://localhost:11434
OLLAMA_MODEL=llama3.1:latest

GROQ_MODEL=openai/gpt-oss-20b
```

- `FETCHLAYER_API_KEY` is required — the collector (`collector/fetchlayer_client.py`) raises a `ValueError` on startup if it is missing.
- `LLM_PROVIDER` selects `ollama` or `groq` for both the LLM sentiment layer and the LLM insights layer.
- `HF_TOKEN` is used by Hugging Face Transformers to authenticate when downloading models from the Hugging Face Hub. It is optional for public models, but should be provided if a model requires authentication or access to the Hugging Face Hub is rate-limited.
- If `LLM_PROVIDER=ollama`, `OLLAMA_HOST`/`OLLAMA_MODEL` must point to a running Ollama server with the model pulled.
- If `LLM_PROVIDER=groq`, `GROQ_API_KEY`/`GROQ_MODEL` are required instead.

### Run Ollama locally (Docker Compose)

The project ships a `docker-compose.yml` that runs the API together with an Ollama server:

```bash
docker compose up -d --build
docker compose exec ollama ollama pull llama3.1:latest
```

Inside Docker Compose the API reaches Ollama at `http://ollama:11434` (overridden automatically in `docker-compose.yml`), not `localhost`.

Alternatively, run Ollama yourself (`ollama serve`, `ollama pull <model>`) and keep `OLLAMA_HOST=http://localhost:11434`.

### Start the API

```bash
uvicorn api:app --reload --port 8000
```

Or via Docker (root `Dockerfile`, `uvicorn api:app --host 0.0.0.0 --port ${PORT:-8000}`):

```bash
docker build -t review-api .
docker run -p 8000:8000 --env-file .env review-api
```

### Access the API

- Base URL: `http://localhost:8000`
- Interactive docs (auto-generated by FastAPI): `http://localhost:8000/docs`
- Dashboard with rendered charts: `http://localhost:8000/dashboard`

### Main collection/analysis flow

Run the full pipeline for an App Store app in one call:

```bash
curl -X POST http://localhost:8000/api/reviews/368677368/collect \
  -H "Content-Type: application/json" \
  -d '{"country":"us","limit":100}'
```

This runs in the background (`BackgroundTasks`) and immediately returns `{"status": "processing", ...}`. Once processing finishes, fetch the result:

```bash
curl http://localhost:8000/api/analysis
```

### Other useful endpoints

- `POST /api/reviews/{app_id}/fetch` — collect and save reviews to `review.json` without running analysis.
  - `country` — 2-letter country code, default: `us`
  - `limit` — number of reviews to collect, default: `100`

- `POST /api/reviews/analyze` — run the full analysis pipeline on the existing `review.json`.

- `GET /api/analysis` — return metrics, sentiment results, and aggregated insights from the latest analysis.

- `GET /api/keywords/{method}` — return negative keyword reports.
  - `method`: `tfidf`, `spacy`, or `keybert`

- `GET /api/reviews/download` — download the raw `review.json` file.

- `GET /api/visualizations/rating-distribution` — return a PNG chart with the rating distribution.

- `GET /api/visualizations/sentiment-distribution` — return a PNG chart with the sentiment distribution.

- `GET /api/visualizations/sentiment-by-rating` — return a PNG chart showing sentiment distribution by rating.

- `GET /api/visualizations/top-negative-terms` — return a PNG chart of the most frequent negative terms or phrases.
  - `method`: `tfidf`, `keybert`, or `spacy-pos` (default: `tfidf`)
  - `kind`: `keywords` or `phrases` (default: `keywords`)


```bash
python collect_reviews.py <APP_ID> --country us --limit 100
# or, to reuse an existing review.json:
python collect_reviews.py --skip-collection
```

## 2. Approach and Key Design Decisions

**Collection.** Reviews are fetched from the FetchLayer API (`collector/fetchlayer_client.py`) and validated into Pydantic `Review` models. The collector is isolated behind its own module so the rest of the pipeline only deals with a list of reviews, not with how they were obtained.

**Cleaning/processing.** `processing/loader.py` validates raw entries (required fields, rating in 1–5) and drops invalid ones with a warning instead of failing the whole batch. `processing/cleaner.py` produces a `clean_review` field (Unicode normalization, HTML/URL stripping, whitespace collapsing) that is fed to all downstream models, while the original review text is preserved unchanged.

**Sentiment analysis.** Three independent methods are run and stored side by side:
- **VADER** (`processing/sentiment.py`) — lexicon-based, English-only, fast deterministic baseline.
- **Transformer** (`processing/transformer_sentiment.py`) — multilingual HuggingFace model (`tabularisai/multilingual-sentiment-analysis`), used as the default "ground truth" label for filtering negative reviews elsewhere in the pipeline, since it supports non-English text.
- **LLM sentiment** (`processing/llm_sentiment.py`) — per-review classification via Ollama or Groq, run in parallel with a thread pool; failed calls are labeled `None` and tracked separately rather than silently miscounted.

**Negative keyword/phrase extraction.** Three complementary methods, all operating on reviews labeled negative by the Transformer model:
- **TF-IDF** (`processing/keywords.py`) — statistical n-gram ranking with a custom stopword list (negation words kept, generic filler/domain words removed).
- **spaCy** (`processing/spacy_keywords.py`) — POS-pattern extraction (e.g. ADJ+NOUN) with lemmatization, English-only.
- **KeyBERT** (`processing/keybert_keywords.py`) — multilingual embedding-based extraction, run per review to preserve document-frequency ranking.

**LLM-based insights.** `processing/llm_insights.py` selects up to 50 negative reviews (lowest rating first), sends a truncated payload to the configured LLM provider, and asks it to group complaints into problem areas with evidence, impact, and a recommendation. The output is validated against a Pydantic `InsightReport` schema, with up to 3 retries if the LLM response doesn't match the schema. This turns raw keywords into an actionable product report rather than stopping at a term list.

**Key architectural decisions.**
- The collector is decoupled from processing so the data source can be swapped without touching analysis code.
- Raw reviews are persisted to `review.json` as a checkpoint, so analysis can be re-run without re-fetching from FetchLayer.
- All results are written as flat JSON files under `results/` and served directly by the API — no database, since the data volume of a single analysis run doesn't justify one.
- Both LLM-dependent steps (`llm_sentiment.py`, `llm_insights.py`) share the same `LLM_PROVIDER` switch (Ollama/Groq), keeping provider selection external to the analysis logic.
- Collection and analysis run as FastAPI `BackgroundTasks` because the full pipeline (external API call, model loading, inference, LLM calls) can take significantly longer than a typical HTTP request.

### LLM Insights

The LLM analyzed the 50 selected negative reviews and identified these recurring problem areas:

1. **Excessive and intrusive ads in the free tier**
2. **Premium pricing perceived as too high**
3. **Playback, shuffle, and playlist management bugs**
4. **App stability and performance issues**
5. **Lack of control over podcast and AI content**

**Summary:**

> Multiple users report recurring frustrations with excessive advertising, high premium pricing, unreliable playback and playlist management, app instability, and limited control over podcast and AI content. These issues degrade the listening experience, drive users toward competitors, and increase churn risk.
